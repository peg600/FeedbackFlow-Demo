# 0004 — 语义 Token、流式响应布局与共享 UI 原语

- 状态：Accepted
- 记录日期：2026-09-19
- 决策日期：2026-08-04—20 分步确认
- 记录性质：历史补录
- 替代：无
- 被替代：无

## 背景与约束

Figma 设计包含多屏宽页面和共享组件，但固定画板的坐标不一定满足真实网页的动态文字和父子尺寸约束。早期登录页绝对定位造成中间宽度位置不合理；手写下拉浮层靠近屏幕边缘时产生横向溢出；各页面重复调整控件导致样式不一致。

## 考虑过的方案

- 按画板坐标逐像素复刻、页面各自硬编码样式：用户在 2026-08-11 明确要求改用自然流式布局并修正设计稿错误。
- 集中语义 Token 和共享基础控件，业务页面通过正常文档流、Flex/Grid 适配：采用。
- 自行维护下拉浮层定位与交互：2026-08-20 用户要求尽量在 shadcn 一类成熟基础上二次开发；实现采用 Radix Select 原语。

## 决策与理由

Figma 负责视觉与交互意图；设计规范在本地快照中解释，运行时 Token 集中于 `globals.css`。以 390px 为基础，按既有断点适配，优先保证语义、可访问性、父子边界及完整内容，而不是机械复制单一画板坐标。

常用控件抽取到 `components/ui`，表格等纯展示部分可共享样式。复杂选择交互基于 Radix 的 Portal/Popper、碰撞处理和键盘行为，再叠加项目 Token、表单字段同步和焦点需求。

## 影响与代价

- 设计修改可以集中传播，避免每个页面各自实现交互基础设施。
- 需维护设计快照、运行 Token 和控件样式的对应关系，不能假设所有 Figma 数值都能原样使用。
- 共享原语仍需针对业务表单与可访问性验证；组件存在不等于所有视口均已验证，也不代表现有代码完全消除了局部尺寸常量。

## 实施与验证

当前存在语义 CSS Token、共享 Button/Input/Select，以及基于文档流的认证页面结构。控件与页面测试包含表单字段、焦点、筛选等行为。2026-08-11 和 2026-08-20 历史对话记录了用户逐次检查与修正；本次仅核对代码及本地设计快照，没有重新读取在线设计或进行浏览器视觉回归。

## 重新评估条件

引入新交互类型、设计 Token 调整或现有控件不能覆盖必要可访问性行为时重新评估扩展方式；避免为了单个画板重新引入页面级绝对坐标排版。
