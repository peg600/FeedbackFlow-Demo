# 0009 — Billing 保持预览，暂不接入支付权限

- 状态：Accepted
- 记录日期：2026-09-19
- 决策日期：2026-09-03 确认；2026-09-18 重申当前范围
- 记录性质：历史补录
- 替代：无（原计划中的完整支付链路尚未实施）
- 被替代：无

## 背景与约束

原项目计划包含 Stripe Checkout、Portal 和 Webhook，但 2026-09-03 用户要求先完成 Billing 页面，支付相关函数使用占位或假数据，不实现 Stripe 功能。2026-09-18 的页面与后端完善要求再次明确排除 Billing。

## 考虑过的方案

- 本阶段接入完整 Stripe 测试支付链路：原计划有该目标，但用户明确延后。
- 提供套餐、用量和价格预览，保留真实支付边界未实现的状态：采用。
- 2026-09-18 另一个会话讨论订阅状态、Webhook 丢失、定时对账和支付后页面更新；这些是方案学习，未见对应实施确认或代码，不视为已采用的对账、Cron 或轮询架构。

## 决策与理由

Billing 只读取当前 Owner 项目的反馈使用量并显示 Free/Pro 预览；不发起真实 Checkout 或 Portal，不根据客户端成功跳转授予 Pro 权限。Webhook 保持明确的 HTTP 501 占位，不能把占位接口描述为已验签或幂等。

当前写入配额仍为每项目 50 条，未建立有效本地订阅驱动的 Pro 解锁。Stripe 相关表或环境变量的预留也不代表支付功能已实现。

## 影响与代价

- 可以展示页面和使用量，暂不依赖 Stripe 配置或支付流程。
- 当前 Demo 不能证明支付回调、订阅生命周期或对账恢复能力；README、价格和 Billing 必须清楚表达预览性质。
- 未来实现支付时需要独立决策和验证，覆盖服务端客户归属、签名、事务幂等和权限来源，不能把本记录当作这些方案的验收。

## 实施与验证

当前 Billing service 返回 Free 预览数据；Webhook 返回 `BILLING_NOT_IMPLEMENTED` 对应错误和 501。存在占位接口测试。本次核对代码与历史范围，没有调用 Stripe，也未执行支付测试。

## 重新评估条件

用户重新确认接入 Stripe 后，以新 ADR 明确支付事实来源、订阅权限规则、Webhook 幂等及恢复策略，链接并替代本阶段的占位决策。
