# 0015 — Billing 配置的安全诊断日志

- 状态：Accepted
- 记录日期：2026-09-29
- 决策日期：2026-09-29
- 记录性质：用户要求定位部署中具体失败的环境变量
- 替代：无；扩展 0010 的配置降级与 0006 的安全日志约定

## 背景与约束

Billing 原先只在任一 Paddle 配置校验失败时返回 null，页面统一显示未配置，操作者无法确定哪个变量失败。凭据不能出现在页面、Action/HTTP 响应或日志中；缺失支付配置时仍需允许公开浏览和 Free 使用。

## 考虑过的方案

- 在页面展示配置详情：能直接诊断，但把部署内部信息暴露给普通访问者，不采用。
- 输出原始 Zod 错误或环境对象：实现简单，但可能包含凭据，不采用。
- 保留现有降级行为，只记录白名单诊断：满足部署排错与保密要求，采用。

## 决策与理由

在 Billing 服务端配置入口对校验失败记录 `Paddle configuration invalid`，错误码复用 `BILLING_NOT_CONFIGURED`。每个 issues 条目只含固定变量名、固定原因和期望格式，不记录值、片段、长度、原始 Zod 错误或其他环境字段。

原因区分缺失、首尾空白、引号、Live 凭据、误填客户端 Token ID 与其他格式错误。分类只用于解释原有 Zod 校验的失败，不自动 trim、替换凭据或改变原有通过条件；通过格式校验也不证明远端凭据有效。

同一个服务端实例对相同诊断最多每分钟记录一次，避免布局、页面与多个服务调用造成重复日志；诊断变化或配置恢复后的再次失败立即记录。抑制状态只保存安全诊断签名和时间，不保存 Secret。该限频不跨实例，不影响每次重新校验或权益判断。

## 影响与代价

- 操作者可在 Vercel Runtime Logs 定位失败变量；页面和接口继续给出安全的通用提示。
- 同一问题在一分钟内刷新可能没有新日志，冷启动或不同实例也可能重复输出。
- 不证明 API 权限、凭据有效期、Webhook Secret 归属或外部支付闭环；这些仍需单独联调。
- 无新依赖、变量、迁移或对账/结账行为变化。

## 实施与验证

2026-09-29 已在配置入口实现诊断。新增 18 项配置回归测试，覆盖缺项、格式分类、日志白名单、重复限频及恢复；全量 51 个测试文件、219 项单元/组件测试通过，lint 和 TypeScript 检查通过。显式将现有 `.env.develop.local` 注入构建子进程后，Next.js 生产构建通过，未修改环境文件。独立安全审查未发现必须修复的问题。

本次未执行数据库集成测试、浏览器 E2E 或真实 Paddle 支付，也未提交或部署代码；线上配置失败原因仍需部署后通过 Runtime Logs 确认。

## 重新评估条件

日志量需要全局控制、需要受保护的运维诊断页面或存在新的凭据类型时重新评估。
