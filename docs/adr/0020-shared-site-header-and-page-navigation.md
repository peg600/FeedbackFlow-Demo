# 0020 — 共享站点 Header 与页面业务导航

- 状态：Accepted
- 记录日期：2026-10-11
- 决策日期：2026-10-11
- 记录性质：当次记录
- 替代：无，扩展 ADR 0004 与 ADR 0019
- 被替代：无

## 背景与约束

首页、控制台、认证页和公开项目页分别维护站点导航，布局、品牌入口和语言按钮不一致。控制台品牌没有首页链接，桌面顶部只有语言切换。用户明确要求所有页面采用首页的 Header 设计，共享同一组件，统一提供品牌首页入口、语言切换及静态作者介绍页 `/profile`，同时允许不同页面配置业务内容。

首页须保持公开，无论是否登录均可访问。已有控制台布局负责会话和项目权限，公开项目区域保留项目名称、反馈/路线图切换及反馈提交入口。不得为纯导航新增数据库查询、修改认证流程或改变公开路由。

## 考虑过的方案

| 方案 | 优点 | 成本与限制 | 取舍理由 |
| --- | --- | --- | --- |
| 各页面继续维护相似 Header | 局部修改方便 | 无法保证所有公共入口与移动端行为同步 | 不采用 |
| 在根布局读取路由与会话，集中判断所有页面导航 | 只需挂载一次 | 把业务路由判断和认证读取耦合到全局，增加公开页依赖 | 不采用 |
| 共享展示组件，由页面/布局显式配置业务导航 | 统一视觉和公共入口，保留既有服务端边界 | 各路由仍需正确组合 Header 与业务区域 | 采用 |

## 决策与理由

- `SiteHeader` 统一渲染首页相同的 Brand、背景、底部分隔线及响应式菜单。品牌始终链接 `/`，作者入口始终链接 `/profile`，语言控件始终提供英文与中文；完整导航统一在 `xl` 展开，较窄视口使用共享菜单，避免首页链接和双语文案拥挤。普通页面使用居中内容宽度，控制台通过 `layout="workspace"` 使用全宽布局，桌面品牌列与既有侧栏宽度一致，右侧操作区与主内容内边距对齐；布局差异仍由同一组件负责。
- `locale`、桌面/移动导航链接、当前页面状态与操作插槽由调用方传入。组件本身不读取 Session、数据库或业务资源；可由服务端页面或控制台客户端外壳组合使用。
- 原生 `details` 菜单的关闭和 Escape 回焦点属于小型客户端岛 `HeaderMenu`；语言持久化继续由已有 `LanguageSwitcher` 负责。业务页面保持默认 Server Component。
- 控制台通过既有布局中的 `DashboardShell` 挂载一次站点 Header，桌面保留工作空间侧栏，移动端业务入口纳入共享菜单；子页面、Loading 和 Error 不重复挂载。
- 公开项目先呈现共享站点 Header，再呈现项目身份和局部导航。项目名称、描述及用户内容保持原文，不把项目名称代替平台品牌。
- 语言切换移除组外框，以 12px 字号、28px 高的紧凑 `English / 中文` 文字按钮组呈现，通过较深的品牌色和略粗的字重标识当前选项，不设置选中或悬停背景；保留键盘焦点样式、`aria-pressed`、语言属性、Cookie 和 URL 保留行为。指向 `/dashboard` 的导航文案统一使用 `Dashboard` / “控制台”。
- 首页不引入身份重定向；提供控制台入口，所有页面都可通过平台品牌返回首页。

## 影响与代价

- 公共入口及菜单交互集中维护，页面只声明业务差异；删除冗余 BasicHeader 和独立控制台移动抽屉。
- 响应式导航在桌面与菜单中各渲染一份业务入口/操作，任一视口只显示对应的一份；测试须在对应导航区域中查询。
- 不新增依赖、环境变量、迁移、数据库写操作或部署配置，不改变资源权限和登录回跳规则。

## 实施与验证

共享组件已接入首页、作者介绍、认证、首次项目创建、控制台布局、公开反馈板/详情/路线图及现有 Loading/Not Found/Error 边界。新增组件回归覆盖公共入口、双语、当前导航状态、控制台单一站点 Header、移动菜单关闭与 Escape 焦点恢复、退出失败可见提示。独立审查发现的公开页 Loading 缺失 Header 已修复，补充了两个加载组件的中文入口测试，并通过只读复核。

初次统一实现的 `pnpm lint`、`pnpm typecheck`、`git diff --check` 与 Production build 通过。构建使用一次性进程内 Secret 和 localhost 占位数据库地址，未修改任何环境文件，也不代表真实生产配置已通过验收。全量单测首轮因旧 Onboarding 文案查询未限定响应式导航区域而有一项失败；修正查询并补齐 Loading 回归后，全量重跑 56 个文件、298 项全部通过。

同日按用户反馈微调语言控件尺寸与颜色状态、控制台导航文案及全宽 Header 对齐；本轮 `pnpm lint`、`pnpm typecheck` 与 6 个相关测试文件的 29 项测试通过，未重新执行构建或真实浏览器视觉检查。本轮属于共享组件的展示配置和样式修正，未改变其业务边界。

同日按认证页的全宽双栏布局补充 `layout="full-width"` 展示配置，登录和注册共用控制台的全宽容器、品牌与操作区边距；不沿用控制台专属侧栏宽度的 Grid 列。居中页面和工作空间仍使用原有配置，此项不改变认证与服务端边界。验证结果见 ADR 0023。

实际 HTTP 检查：首页、作者介绍、登录、注册的英文和中文请求均返回 200，且各有一套站点 Header、品牌首页链接、作者链接和语言入口；未知路径返回 404 并保留公共 Header。本地 `/p/demo` 对应资源不存在，返回流式 Not Found，未据此声称真实项目页面已验收。项目与控制台组合由组件测试验证，未注册账号或写入数据。

本地 `docs/design-system.md` 仍缺失；本次成功读取 Figma `12:376` 设计 Token 与截图，确认继续复用现有 Brand 和语义 Token。Chrome 连接两次返回 `nodeRepl.fetch request failed`，真实浏览器的视口、登录态跨页面导航和视觉验证尚未完成。

## 重新评估条件

需要在更多页面动态展示账户菜单、增加更多页面级导航或共享布局无法保证单一站点 Header 时，重新评估导航配置和布局归属；不得仅为展示入口扩大首页服务端渲染的数据库依赖。首页的身份展示扩展见 ADR 0021。
