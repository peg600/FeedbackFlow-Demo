# 0023 — 首页业务入口按会话状态导航

- 状态：Accepted

- 决策日期：2026-10-11

- 替代：无，扩展 [ADR 0021](0021-session-aware-home-header.md)

## 背景与约束

首页 Header 已按会话展示登录或退出，但首屏和底部的创建反馈板、Free 套餐、Pro 套餐四处入口仍写死注册或登录地址。已登录用户返回首页后会再次进入注册或登录页。首页必须继续对所有人开放，不因账户状态强制离开首页。

每用户只有一个项目，控制台已有服务端逻辑区分未登录、尚未创建项目和已有项目。首页无需再查询项目或套餐，也不能用客户端状态代替服务端授权。

## 考虑过的方案

| 方案 | 优点 | 成本与限制 | 取舍理由 |
| --- | --- | --- | --- |
| 首页服务端查询 Session 和项目，拼接每个目标 | 首屏状态明确 | 公开正文依赖认证数据库，重复控制台分流 | 不采用 |
| 所有入口固定指向受保护页面 | 无需客户端判断 | 确认未登录的创建入口会从注册变为登录 | 不采用 |
| 小型客户端链接复用官方会话状态 | 全部入口随登录状态更新，公开正文保持服务端渲染 | 等待与失败时需要明确回退目标 | 采用 |

## 决策与理由

- 新增 `HomeActionLink`，仅负责首页创建、Free 和 Pro 入口的文案及目标。它与 Header 使用同一个 `authClient.useSession()` 共享会话存储，无独立请求实现、手动 Cookie 判断或项目查询。
- 确认未登录时，创建和 Free 进入 `/register`；Pro 保留 `/login?returnTo=/dashboard/billing`。
- 已登录时，创建和 Free 改为“控制台”并进入 `/dashboard`，Pro 改为“订阅与账单”并进入 `/dashboard/billing`。已有项目进入控制台，尚未创建项目由现有服务端访问逻辑引导至 `/onboarding`，不新增第二个项目。
- 初次等待或会话读取失败且无已知会话时，四处入口统一显示“控制台”并进入 `/dashboard`，由服务端判断身份；不把未知状态当作匿名，也不阻塞公开内容。这样避免未知身份的 Pro 入口承诺账单目标，却被既有服务端登录分流回控制台。确认登录后 Pro 再切换为账单入口。Header 保留既有等待、错误及重试展示。
- 演示、公开路线图、作者链接和页内内容与会话无关，继续保持公开目标。

## 影响与代价

- 首页四处业务 CTA 与 Header 的会话状态保持一致，登录和退出后可更新目标及中英文文案。
- 未知身份时点击会进入服务端认证分流，可能需要登录；只有确认匿名后才直接展示注册入口。
- 无数据库、迁移、环境变量、依赖、认证策略或外部服务变更。

## 实施与验证

已替换全部四处正文业务入口；补充页面级回归覆盖匿名、登录后与退出后更新、等待、读取失败以及中文入口。最终 lint、typecheck、Production build、diff 检查及全量 57 个文件、312 项单元/组件测试通过。构建仅在进程内使用一次性认证 Secret 和 localhost 占位数据库地址，不修改环境文件，不代表真实生产配置验收。

本地首页、注册页、登录页 HTTP 均返回 200。Chrome 连接失败后成功使用内置浏览器检查：注册页在 390×844、768×720、1023×480、1024×900、1279×720 和 1440×900 下无横向溢出，Header 可见控件均在视口内；1280px 截图确认全宽品牌及导航布局。匿名首页的四处业务入口目标正确，实际点击创建反馈板进入注册页。已登录、退出后更新、等待与失败分支由组件测试验证，未操作真实账号或写入数据库。

独立只读审查提出的未知身份 Pro 回跳限制已按通用控制台回退修正并复核通过，无剩余阻断问题。

## 重新评估条件

需要按具体套餐展示升级/降级、按项目名称导航，或希望匿名 Pro 体验也自动保留注册后的账单目标时，另行评估业务入口与服务端分流，不在首页复制权益判断。
