# 0024 — 登录页公开指定演示账号凭据

- 状态：Accepted
- 记录日期：2026-10-12
- 决策日期：2026-10-12
- 记录性质：当次记录
- 替代：无
- 被替代：无

## 背景与约束

登录页此前硬编码的示例凭据与实际演示账号不一致，无法登录。改为仅在配置文件提供凭据后，用户明确要求恢复页面展示，方便面试者直接复制粘贴。指定演示 Owner 账号可以公开，普通账号与应用 Secret 仍须保密；Development 与 Production 使用各自数据库及演示密码。

## 考虑过的方案

| 方案 | 优点 | 成本与限制 | 取舍理由 |
| --- | --- | --- | --- |
| 页面硬编码邮箱密码 | 直接可用 | 容易与 Seed 失配，真实值进入 Git | 不采用 |
| 仅在私有配置提供凭据 | 不向浏览器公开 | 面试者无法直接使用，不满足需求 | 不采用 |
| 服务端读取指定演示配置并在页面显示 | 同环境可对应 Seed，访客直接复制 | 指定演示账号有意公开 | 采用 |

## 决策与理由

仅当 `DEMO_LOGIN_ENABLED` 严格等于 `true` 时，服务端使用现有登录 Schema 校验 `DEMO_USER_EMAIL` 与 `DEMO_USER_PASSWORD`，向客户端显式投影 `{ email, password }`。邮箱按 Seed 规则规范化，密码保持原值。缺失、无效或未开启时显示演示登录暂不可用，不使正常登录失败，也不回退到假凭据。

页面分行展示可选择的完整邮箱密码，长密码允许换行。配置继续在 Git 外管理，但启用后两项演示凭据会有意发送给所有浏览器访问者。此开关独立于 Seed 确认开关，不自动创建账号、重置密码或绕过正常认证、限流与权限。

## 影响与代价

- 面试者无需访问配置文件即可体验共享演示工作空间。
- 该账号拥有真实 Owner 管理权限，访客可能修改演示项目与反馈；不增加只读角色或自动重置机制。
- 数据库连接、Better Auth 与 Paddle Secret 不属于客户端投影；支付仍限定 Sandbox。
- 无数据库结构变更或新增依赖。部署环境须配置与自身 Seed 对应的三项展示变量，并重新部署才生效。

## 实施与验证

实现服务端配置投影、登录页展示、中英提示、可选配置及页面回归测试。本地展示配置与已 Seed 的 develop 账号对应；已准备忽略的 Production 配置文件，未修改 Vercel 或部署。

本次实际执行：lint、typecheck、58 个文件共 323 项单元测试及 production build 通过。构建首次因隔离环境无法下载既有 Inter 字体失败，允许联网重试后通过。

本地 Playwright 浏览器在 390px 宽度读取页面显示的邮箱密码，确认与 develop Seed 匹配并无横向溢出；使用这些显示值正常登录并进入控制台，验证会话后退出，确认会话清理。页面 HTML 检查未包含所检查的数据库连接、认证密钥或 Paddle 服务端 Secret。只读安全复核通过。Production 页面展示与真实登录尚未部署验证。

## 重新评估条件

演示账号权限、公开访问策略或数据保留需求改变时重新评估。若增加真实支付或敏感业务数据，须另行决策演示隔离方式。
